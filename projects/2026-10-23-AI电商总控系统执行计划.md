# AI 电商总控系统 · 合法合规执行计划（v1.1）

> 融合四块拼图：FDE 方法论（怎么练）、电商自动化系统（做什么）、REA 自动逆向工程流程（怎么抄作业）、云端 AI 包工头总控智能体（谁来盯）。
> 总纲：**Start with the outcome → Do what it takes → Follow with scale**（H1 先存在，H4 再优雅）。
> v1.1 更新：包工头自身 Evals（对齐行业第一店铺运营基准）+ 包工头自愈机制（REA 能力内化，应对平台限制/政策调整/流程低效）。

## 〇、系统全景

```
jeans（出题/拍板）
   ↓ 场景/痛点
┌──────────────────────────────────────────────┐
│  云端 AI 包工头（Orchestrator，7×24 值守）      │
│  分解任务 → 派发工种Agent → 监控 → 异常升级     │
│  → 三类通知：待决策 / 异常报警 / 每日战报        │
│  自身能力：Evals 自评（对标行业第一）+ 自愈修复   │
└──────────────────────────────────────────────┘
   ↓ 派工
 REA逆向Agent → 选题/研究Agent → 选品Agent → 供应商Agent
      → 上架Agent → 内容Agent → 投放Agent → 复盘Agent ─┐
   ↑___________________________________________│（数据飞轮回灌）
```

**底层三件套（所有 Agent 共享，先于任何 Agent 上线）：**
1. **数据底座**：一张真实库表起步（选题库/痛点库/订单库），一切产出结构化落库——Agent 不复述、不失忆。
2. **全局红线文件**（7 条一票否决）：无授权登录态抓取、RPA 模拟人操作、刷量假互动、虚假主体群控、规避广告审核、未标识 AI 内容、绕过速率限制。新 Agent 上线前先读它。
3. **分级授权表**：🟢全自动／🟡AI做人确认（金额/风险阈值写明）／🔴人做AI辅助。信任达标一个环节，放权一个环节。

## 一、四块拼图如何咬合

| 拼图 | 在系统里的角色 | 核心机制 |
|---|---|---|
| 云端 AI 包工头 | 总控：派工、盯进度、收异常、推通知；**自身带 Evals 与自愈能力** | 每个工种Agent有明确工单格式（输入/产出/时限/升级条件）；低置信度必升级人工——与护盾"低置信转人工"同一思想 |
| REA 自动逆向工程 | 双层用途：①选题研究引擎（拆爆款）②**包工头的自愈引擎（拆问题）** | 只拆合法可得数据：官方API、公开榜单、合规数据服务商、自购样品实测；⛔不爬登录态、不盗用素材、不侵犯专利商标 |
| FDE 方法论 | 推进纪律与验收标准 | H1→H4 两段式；Evals 先行；每月"让自己过时"复盘 |
| 电商自动化九环节 | 战场本体 | 按风险从低到高分四阶段放权（见下） |

## 二、REA 自动逆向工程流程（合规版定义，双层用途）

### 2.1 对外：拆爆款（选题与研究引擎）

**输入**：包工头下发的选题方向或品类假设。
**流水线**：
1. **找靶子**：官方/合规数据源（TikTok Creative Center、Amazon Best Sellers、Google Trends、EchoTik/Kalodata 类授权服务）筛出近 30 天上升期爆款/爆品候选；
2. **拆要素**：结构化拆解——卖点排序、价格带、内容钩子（前3秒）、评论区高频痛点、差评缺口（=我们的机会）；
3. **合规校验**：专利/商标/认证/禁限售自动初筛，一票否决项命中即弃；
4. **出工单**：每个候选产出"逆向工程报告"（证据链+差异化切入点+风险标注），进选题库待我打分。
**验收物**：选题评分卡历史库（我的打分=评估基准，Agent 自评达标才推送）。

### 2.2 对内：拆自己（包工头自愈引擎，见第五节）

同一套 REA 方法指向系统自身：拆行业第一店铺的运营做法、拆政策文件的变化点、拆自家流水线的低效环节——产出修复/补强工单。

## 三、包工头自身 Evals：对齐行业第一的运营基准

> 原则：包工头不能只管派工不管自己干得怎么样。它的尺子不是"流程跑没跑"，而是"**和该类目行业第一店铺的公开运营数据比，差距在缩小还是扩大**"。

### 3.1 基准库（Benchmark Base）

- **标的选择**：每个进入的品类，锁定 1-2 家该类目排名第一梯队的店铺/品牌作为对标基准；
- **数据来源（全部合规）**：官方榜单与店铺公开页、授权数据服务（EchoTik/Kalodata/卖家精灵类）、对方公开财报/访谈/招聘信息（推断组织与节奏）、自购样品实测；
- **基准指标（按品类校准）**：

| 维度 | 对标指标 | 我方数据来源 |
|---|---|---|
| 选品速度 | 上新频率、跟热点响应时长 | 包工头派工时间戳 |
| 测品效率 | 测品周期（天）、单品测试成本 | 投放Agent数据 |
| 内容产能 | 日产出条数、爆款率（播放/互动分位） | 内容Agent+平台官方数据 |
| 转化效率 | 转化率、客单价、ROI、退货率 | 一方数据 |
| 供应链 | 采购成本占比、交期 | 供应商Agent数据 |

### 3.2 运行机制

- **每周对标报告**：包工头自动产出"我方 vs 行业第一"差距表，标注缩小/扩大的指标；
- **及格线**：上线初期我方效率达到基准的 30% 为存活线，每月目标为差距收窄；连续 4 周无收窄 → 触发自愈流程（第五节）；
- **Evals 落库**：每份对标报告+我的处置决定进入评估库，成为包工头自评和迭代的历史基准。

## 四、四阶段推进（信任曲线决定排期，非技术排期）

| 阶段 | 环节 | 授权级别 | 验收标准（达标才进下一阶段） |
|---|---|---|---|
| **S1（第1-2周）** | REA逆向 + 选题 + 研究 + 复盘 | 🟢 全自动（纯信息流零风险） | 我连续 5 天给 Agent 推荐选题的采纳率 ≥50%；选题库 ≥50 条带证据记录；**首份行业对标基准报告产出** |
| **S2（第3-4周）** | 上架 + 投放 | 🟢阈值内全自动，超阈值🟡 | 官方 API 跑通一次真实刊登+一笔小预算 AB 测试；首份自动复盘产出 |
| **S3（第2个月）** | 内容生产 + 矩阵测品 | 🟡 AI做+质检Agent把关，我抽检 | 日产 3 条过质检内容；广告 AB 测试替代账号矩阵 |
| **S4（第3个月起）** | 选品 + 供应商沟通 | 🟡 批量询盘自动，签约🔴我批 | 供应商评分卡落库；单笔采购全流程走通一次 |

**每阶段 H1→H4**：先用最糙方式跑通（哪怕手动+AI拼），跑通前禁止过度设计；卡在"设计中"超两周，强制降级上线更糙版本。

## 五、包工头自愈机制：检测 → 逆向诊断 → 修复 → 验证

> 应对三类扰动：**平台限制（风控/接口变更）、国家政策调整、自家工作流低效**。
> 原则：自愈的"诊断和提案"全自动（🟢），"涉及花钱、合规边界、上架/投放参数"的修复落地需我批准（🟡）。**修复永远不走规避对抗路线**——平台限制的合法解是换合规通道，不是换对抗技术。

### 5.1 三类触发器

| 扰动 | 检测方式 | 响应时限 |
|---|---|---|
| 平台限制（风控/降权/接口下线） | API 错误率监控 + 政策监控子Agent（开发者协议/公告变更比对） | 报警即时，修复提案 ≤24h |
| 国家政策调整 | 监控官方渠道（商务部/海关/税务/市监总局公告、平台合规通知），AI 摘要比对影响面 | 日报级别 |
| 工作流低效 | 对标报告连续 4 周差距未收窄 / 环节耗时或成本超阈值 / 复盘Agent归因结论 | 每周评估 |

### 5.2 自愈流水线（REA 内化）

1. **逆向诊断**：拆问题——是通道被封（换接口/换服务商/换渠道插件）、规则变了（更新红线文件与质检规则）、还是做法落后（拆行业第一当期做法，找差距根源）；
2. **修复提案**：产出"问题归因 + 2-3 个修复选项 + 各自成本/风险/合规性"的工单推给我；
3. **落地**：批准后热更新对应技能包/连接器（插件化架构保证主干不动），修复记录落库；
4. **回归验证**：用既有 evals 重跑受影响环节，质量不低于修复前才关闭工单——**修复不许引入退化**；
5. **沉淀**：每次修复转化为一条新的红线/质检规则/技能包，同类问题第二次出现时全自动处理（🟡降🟢）。

## 六、渠道与合规架构

- **三路并行**：Amazon + TikTok Shop + 独立站（Shopify）。独立站是政策避风港与一方数据最终沉淀地。
- **身份阳光化**：开发者账号、企业资质、正式 API 权限、ISV 身份，全部注册在前。
- **内容合规**：AI 生成必标识；质检Agent（查重/信息增量/违禁词）把关；质量门槛 > 产量。
- **数据获取**：官方数据源 + 授权数据服务商 + 自有店铺一方数据飞轮，逐步降低外部依赖。

## 七、非实体扩展线（电商跑稳后启动）

软件/SaaS 分销为主战场（授权门槛最低、交付全自动）：独立站+自动交付（卡密/激活码）+内容获客最小闭环 → 拿销售记录谈游戏 Key 授权 → 最后评估票务（猫眼官方分销打底、淘票票对冲、销量数据谈院线直签包销）。**授权资产台账**（区域/返点/有效期/续约日）由包工头维护，提前 90 天提醒续约。

## 八、复盘仪式

- **每月三问**：①这个月 AI 让我哪段工作过时了？（答不上=停滞警报）②哪个环节信任达标，🟡可降🟢？③哪个 Agent 经 evals 检验在变好、哪个在赌运气？
- **每周加一问（v1.1 新增）**：④包工头的对标报告里，哪个指标差距在扩大？触没触发自愈？
- **每阶段三问**（保留原纪律）：是否解决真实卡点？是否留下可复用资产？是否挤占主线？
