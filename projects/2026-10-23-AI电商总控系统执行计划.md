# AI 电商总控系统 · 合法合规执行计划（v1.0）

> 融合四块拼图：FDE 方法论（怎么练）、电商自动化系统（做什么）、REA 自动逆向工程流程（怎么抄作业）、云端 AI 包工头总控智能体（谁来盯）。
> 总纲：**Start with the outcome → Do what it takes → Follow with scale**（H1 先存在，H4 再优雅）。

## 〇、系统全景

```
jeans（出题/拍板）
   ↓ 场景/痛点
┌──────────────────────────────────────────────┐
│  云端 AI 包工头（Orchestrator，7×24 值守）      │
│  分解任务 → 派发工种Agent → 监控 → 异常升级     │
│  → 三类通知：待决策 / 异常报警 / 每日战报        │
└──────────────────────────────────────────────┘
   ↓ 派工
 REA逆向Agent → 选题/研究Agent → 选品Agent → 供应商Agent
      → 上架Agent → 内容Agent → 投放Agent → 复盘Agent ─┐
   ↑___________________________________________│（数据飞轮回灌）
```

**底层三件套（所有 Agent 共享，先于任何 Agent 上线）：**
1. **数据底座**：一张真实库表起步（选题库/痛点库/订单库），一切产出结构化落库——Agent 不复述、不失忆。
2. **全局红线文件**（7 条一票否决）：无授权登录态抓取、RPA 模拟人操作、刷量假互动、虚假主体群控、规避广告审核、未标识 AI 内容、绕过速率限制。新 Agent 上线前先读它。
3. **分级授权表**：🟢全自动／🟡AI做人确认（金额/风险阈值写明）／🔴人做AI辅助。信任达标一个环节，放权一个环节。

## 一、四块拼图如何咬合

| 拼图 | 在系统里的角色 | 核心机制 |
|---|---|---|
| 云端 AI 包工头 | 总控：派工、盯进度、收异常、推通知 | 每个工种Agent有明确工单格式（输入/产出/时限/升级条件）；低置信度必升级人工——与护盾"低置信转人工"同一思想 |
| REA 自动逆向工程 | 选题与研究环节的引擎：合规拆解已验证的爆款 | 只拆合法可得数据：官方API、公开榜单、合规数据服务商、自购样品实测；⛔不爬登录态、不盗用素材、不侵犯专利商标 |
| FDE 方法论 | 推进纪律与验收标准 | H1→H4 两段式；Evals 先行；每月"让自己过时"复盘 |
| 电商自动化九环节 | 战场本体 | 按风险从低到高分四阶段放权（见下） |

## 二、REA 自动逆向工程流程（合规版定义）

**输入**：包工头下发的选题方向或品类假设。
**流水线**：
1. **找靶子**：官方/合规数据源（TikTok Creative Center、Amazon Best Sellers、Google Trends、EchoTik/Kalodata 类授权服务）筛出近 30 天上升期爆款/爆品候选；
2. **拆要素**：结构化拆解——卖点排序、价格带、内容钩子（前3秒）、评论区高频痛点、差评缺口（=我们的机会）；
3. **合规校验**：专利/商标/认证/禁限售自动初筛，一票否决项命中即弃；
4. **出工单**：每个候选产出"逆向工程报告"（证据链+差异化切入点+风险标注），进选题库待我打分。
**验收物**：选题评分卡历史库（我的打分=评估基准，Agent 自评达标才推送）。

## 三、四阶段推进（信任曲线决定排期，非技术排期）

| 阶段 | 环节 | 授权级别 | 验收标准（达标才进下一阶段） |
|---|---|---|---|
| **S1（第1-2周）** | REA逆向 + 选题 + 研究 + 复盘 | 🟢 全自动（纯信息流零风险） | 我连续 5 天给 Agent 推荐选题的采纳率 ≥50%；选题库 ≥50 条带证据记录 |
| **S2（第3-4周）** | 上架 + 投放 | 🟢阈值内全自动，超阈值🟡 | 官方 API 跑通一次真实刊登+一笔小预算 AB 测试；首份自动复盘产出 |
| **S3（第2个月）** | 内容生产 + 矩阵测品 | 🟡 AI做+质检Agent把关，我抽检 | 日产 3 条过质检内容；广告 AB 测试替代账号矩阵 |
| **S4（第3个月起）** | 选品 + 供应商沟通 | 🟡 批量询盘自动，签约🔴我批 | 供应商评分卡落库；单笔采购全流程走通一次 |

**每阶段 H1→H4**：先用最糙方式跑通（哪怕手动+AI拼），跑通前禁止过度设计；卡在"设计中"超两周，强制降级上线更糙版本。

## 四、包工头总控智能体 · 工单与值守规范

- **派工**：我只说场景/痛点（一句话），包工头拆成工单派给工种 Agent，工单含：输入数据、产出格式、时限、置信度阈值、升级条件。
- **值守**：定时任务驱动；每个节点状态写数据底座；异常（API失败/预算超支/政策变更）立即报警。
- **通知三级**：「待你决策」（需我点批准）／「异常报警」（我马上看）／「每日战报」（扫一眼）。我的时间只花第一类。
- **政策监控子Agent**：定期比对各平台开发者协议与公告变更，变化即通知。
- **插件化**：平台适配层可插拔——某平台改政策，换接口迁移，主干不动；定制代码是负债，通用能力+技能包是资产。

## 五、渠道与合规架构

- **三路并行**：Amazon + TikTok Shop + 独立站（Shopify）。独立站是政策避风港与一方数据最终沉淀地。
- **身份阳光化**：开发者账号、企业资质、正式 API 权限、ISV 身份，全部注册在前。
- **内容合规**：AI 生成必标识；质检Agent（查重/信息增量/违禁词）把关；质量门槛 > 产量。
- **数据获取**：官方数据源 + 授权数据服务商 + 自有店铺一方数据飞轮，逐步降低外部依赖。

## 六、非实体扩展线（电商跑稳后启动）

软件/SaaS 分销为主战场（授权门槛最低、交付全自动）：独立站+自动交付（卡密/激活码）+内容获客最小闭环 → 拿销售记录谈游戏 Key 授权 → 最后评估票务（猫眼官方分销打底、淘票票对冲、销量数据谈院线直签包销）。**授权资产台账**（区域/返点/有效期/续约日）由包工头维护，提前 90 天提醒续约。

## 七、复盘仪式

- **每月三问**：①这个月 AI 让我哪段工作过时了？（答不上=停滞警报）②哪个环节信任达标，🟡可降🟢？③哪个 Agent 经 evals 检验在变好、哪个在赌运气？
- **每阶段三问**（保留原纪律）：是否解决真实卡点？是否留下可复用资产？是否挤占主线？
